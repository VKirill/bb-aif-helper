# Маршруты поиска

Маршрут (`route`) задаёт порядок волн, обязательные углы, правила сведения и критерий остановки для конкретного типа задачи. Допустимые значения `route`, `waves` и остальных перечислений описаны в разделе «Словари» [evidence.md](evidence.md); типы источников, инструменты и лимиты — в [sources.md](sources.md); разбор вопроса, линзы и шаблоны запросов — в [angles.md](angles.md).

## 1. Таблица маршрутов

| Маршрут (`route`) | `dev` | `ideas` | Картирующая волна (`map`) | Когда выбирать |
|---|---|---|---|---|
| `scan` | да | да | она же единственная | Быстрая первичная разведка новой темы или низкорискового вопроса |
| `deep` | да | да | обязательна | Незнакомая предметная область, высокий риск, нужны карта площадок и разбор по направлениям |
| `compare` | да | да (конкуренты) | по желанию | Выбор библиотеки, архитектуры, сервиса или сравнение конкурентов |
| `debug` | да | нет | пропускается | Конкретный сбой, регрессия, ошибка сборки или вопрос «как сделать» |
| `intl` | нет | да | обязательна на обоих рынках | Локальных данных мало или нужно сопоставить международный опыт с локальным рынком |
| `science` | да | да | нет | Нужны механизмы, ограничения, бенчмарки или проверка научной обоснованности |
| `factcheck` | да | да | нет | Проверка рекламных обещаний, заявленных свойств или спорных тезисов против опыта |
| `trend` | да | да | нет (нужны 2 периода) | Проверка, меняется ли частота проблем, подходов или спроса во времени |
| `delta` | да | да | нет (берётся прежний корпус) | Повторный запуск по уже собранной папке `.ai-factory/scout/<slug>/` |

### Паспорта маршрутов

#### `scan` — быстрая разведка
- **Когда выбирать:** нужно быстро понять, где обсуждают тему, какие термины используют и есть ли смысл идти глубже.
- **Волны:** одна волна (`map` по шаблону из [scout-brief.md](scout-brief.md)), 2–3 разведчика.
- **Обязательные углы:** минимум один `discovery` по живым обсуждениям и один `constraint` (скептический взгляд или ограничения).
- **В `report.md`:** `## Карта источников`, `## Перекос`, `## Установлено`, `## Неизвестно` (с кандидатными вопросами), `## Следующий шаг`. Выводы о «главной боли» или большинстве запрещены.
- **Когда остановиться:** после первой волны, если картина площадок и терминов собрана; при необходимости продолжения запускается `deep`.

#### `deep` — широкий → узкий
- **Когда выбирать:** сложная тема, высокая цена ошибки (деньги, безопасность, лицензии, необратимое решение) или неясные границы направлений.
- **Волны:** сначала обязательная волна `map` (1–2 разведчика), затем 1+ волн `narrow` по выделенным направлениям (подробно — в разделе 2).
- **Обязательные углы:** в `map` — обзор площадок; в `narrow` — по каждому направлению рабочий угол + зеркало (`mirror_of`), а в `ideas` дополнительно боли, обходы и конкуренты.
- **В `report.md`:** `## Карта источников`, `## Перекос`, `## Установлено` с разбивкой по направлениям, противоречия, покрытие, для `ideas` — порядок возможностей из `opportunities.yaml`, `## Неизвестно`, `## Следующий шаг`.
- **Когда остановиться:** по правилу насыщения (раздел 6).

#### `compare` — выбор инструмента / конкурентов
- **Когда выбирать:** в `dev` — сравнение библиотек, протоколов, подходов; в `ideas` — сравнение существующих продуктов, цен, ограничений и жалоб.
- **Волны:** `map` по желанию (если неизвестны ключевые альтернативы); основная — `narrow`.
- **Обязательные углы:** по каждому варианту критерии выбора и `constraint` (ограничения, причины отказа, скрытые издержки); в `ideas` — отдельный угол на обещания конкурентов против отзывов после внедрения.
- **В `report.md`:** сравнительные выводы по критериям, дисквалифицирующие факторы (`disqualifier`), `## Перекос`, противоречия контекстов, `## Неизвестно`, `## Следующий шаг`.
- **Когда остановиться:** когда у каждого кандидата есть проверяемые плюсы, ограничения и ясен контекст выбора.

#### `debug` — how-to / сбой (только `dev`)
- **Когда выбирать:** воспроизводимая ошибка, регрессия версии, ограничения конкретного API или выбор рабочего паттерна.
- **Волны:** `map` пропускается; сразу `narrow`.
- **Обязательные углы:** официальный источник (релизы, доки, issue tracker) + готовые решения/обходы + скептик (`version_scope`, условия среды, при которых обход ломается).
- **В `report.md`:** симптом vs возможные причины (без выбора одной причины без доказательств), подтверждённые обходы с `version_scope`, `## Перекос`, `## Неизвестно`, `## Следующий шаг`.
- **Когда остановиться:** найдена подтверждённая причина или рабочий обход с известными ограничениями, либо зафиксировано, что в публичных трекерах ответа нет.

#### `intl` — международная развилка (только `ideas`)
- **Когда выбирать:** на основном локальном рынке мало обсуждений, либо продукт адаптирует зарубежную практику и важно не перенести чужой контекст вслепую.
- **Волны:** обязательна `map` на обоих рынках, затем параллельные `narrow`-выборки по одинаковым направлениям (раздел 4).
- **Обязательные углы:** минимум по одному парному набору направлений для международного и локального рынков; при нехватке локальных данных — отдельный угол проверки локальных ограничений.
- **В `report.md`:** `## Карта источников`, матрица сравнения рынков, цепочки переноса со строкой `что нельзя утверждать`, `## Перекос`, порядок возможностей (с проверкой `market: both`), `## Неизвестно`, `## Следующий шаг`.
- **Когда остановиться:** когда для каждого ключевого направления заполнены статус в матрице рынков и оценка риска переноса.

#### `science` — механизм и ограничения
- **Когда выбирать:** нужно понять, почему явление работает именно так, какие есть границы применимости, метрики и научная база, а не просто мнения пользователей.
- **Волны:** `map` не требуется; сразу `narrow` с двумя независимыми ветвями (пользовательские/практические наблюдения и научные статьи).
- **Обязательные углы:** `measurement` / `discovery` по научным источникам (с карточкой научной работы из [evidence.md](evidence.md)) + практический или скептический угол на переносимость в реальную среду.
- **В `report.md`:** разделение «что наблюдают практики / какой механизм описан / чего исследование не доказывает / проверяемое следствие», `## Перекос`, `## Неизвестно`, `## Следующий шаг`.
- **Когда остановиться:** механизм, ограничения и пробелы переноса зафиксированы; при доступности только аннотации выводы о методе не строятся.

#### `factcheck` — обещания против опыта
- **Когда выбирать:** нужно проверить рекламные заявления продукта, библиотеки или бенчмарка перед ставкой на решение или позиционированием.
- **Волны:** `map` не требуется; сразу `narrow`.
- **Обязательные углы:** источник обещаний (`origin: vendor` / документация) + независимый опыт эксплуатации (`origin: user` / issues / тесты) + скептик (контрпримеры и поломки).
- **В `report.md`:** таблица обещаний со статусами (`подтверждено` | `частично` | `не подтверждено` | `требует теста конкретной модели`), строгое отделение рекламы от опыта, `## Перекос`, `## Неизвестно`, `## Следующий шаг`.
- **Когда остановиться:** каждое вынесенное в план обещание получило статус со ссылками или перенесено в `## Неизвестно`.

#### `trend` — сравнение периодов
- **Когда выбирать:** нужно выяснить, усиливается ли проблема, растёт ли переход на альтернативу или меняется ли характер жалоб со временем.
- **Волны:** `map` не требуется; сразу `narrow` с жёсткой разбивкой запросов по двум временным окнам.
- **Обязательные углы:** ранний период (`period_1`) и поздний период (`period_2`) по сопоставимым площадкам и запросам + `constraint` на смену правил/аудитории самой площадки.
- **В `report.md`:** сравнение двух периодов с явными диапазонами `source_date`, динамика без подмены сдвигом площадки, `## Перекос`, `## Неизвестно`, `## Следующий шаг`.
- **Когда остановиться:** оба периода собраны по сопоставимым источникам или установлено, что данных по одному из периодов недостаточно.

#### `delta` — обновление прошлой разведки
- **Когда выбирать:** по умолчанию при повторном запуске `/aif-scout` по уже существующей папке `.ai-factory/scout/<slug>/`, если владелец не попросил полный перезапуск с архивом.
- **Волны:** `map` не запускается; переиспользуется прежний корпус `corpus/*.yaml`, дозапрашиваются только затронутые углы или новые даты (`-w2`, `-w3`).
- **Обязательные углы:** только направления с новыми событиями, протухшим `as_of` или открытыми вопросами из прошлого `report.md`; неизменённые части не пересобираются.
- **В `report.md`:** перед сборкой перенеси прежний `report.md` в `archive/<YYYY-MM-DD-HHMM>/report.md`, затем собери новый `report.md` как **полный текущий синтез**: неизменённые выводы переносятся с прежними ссылками, к ним добавляется раздел `## Изменения с прошлой разведки` с пятью списками. Так передача в `/aif-explore` по `report.md` не теряет ещё верные выводы.
- **Когда остановиться:** когда закрыты или обновлены целевые открытые вопросы без лишнего пересбора стабильного корпуса.

## 2. Маршрут `deep`: широкий → узкий

`deep` разделяет поиск площадок и углубление в конкретные вопросы, чтобы не искать наугад в неподходящих сообществах.

1. **Картирующая волна (`map`):** 1–2 разведчика обходят тему широко (по шаблону `map` в [scout-brief.md](scout-brief.md)). Волна возвращает только:
   - карту площадок (`source_map`: площадка, тип, язык, почему подходит, что там обсуждают);
   - повторяющиеся термины и формулировки;
   - типы пользователей (кандидатные сегменты);
   - кандидатные вопросы для углубления.
   На этапе `map` запрещено делать выводы о большинстве аудитории и объявлять «главную боль».
2. **Разбиение на направления:** координатор группирует кандидатные вопросы по этапам пути пользователя (для `ideas`, см. [angles.md](angles.md)) или по осям пропущенного (для `dev`).
3. **Узкие волны (`narrow`):** каждое направление становится узким углом со своим зеркальным углом (`mirror_of`). Узкие разведчики получают конкретные площадки из `source_map` и ищут дословные цитаты, контекст и контрпримеры.
4. **Сводка:** весь собранный корпус обрабатывается веером линз (раздел 6), проходит аудит перекоса и проверку покрытия, после чего собирается `report.md` (и `opportunities.yaml` в режиме `ideas`).

## 3. Парные контрасты как генераторы углов

Одиночный угол на подтверждение собирает одностороннюю выборку. Парные контрасты заставляют искать противоположную сторону в тех же условиях.

**Правило:** контраст — это пара углов на одном корпусе или пара запросов одного разведчика, отмеченная полем `contrast`.

| Контраст (`contrast`) | Что сравниваем | Зачем нужен и что запрещено | Нейтральный пример (`dev` / `ideas`) |
|---|---|---|---|
| **Похвала ↔ разочарование и отказ** | Положительные отзывы ↔ возражения, причины отказа/возврата, раздражители, которые не меняют решение | Не даёт частой эмоции или комплименту стать главным критерием | `ideas`: за что хвалят сервис авто-учёта расходов ↔ почему отменяют подписку после первого месяца |
| **Новички ↔ опытные ↔ отказавшиеся** | Вопросы, термины, уверенность и барьеры в каждом сегменте отдельно | Запрещено смешивать сегменты в один усреднённый портрет | `dev`: первый запуск фоновой очереди ↔ продакшен на пиках ↔ миграция с неё на брокер сообщений |
| **До покупки ↔ после нескольких использований** | Ожидания и критерии выбора до старта ↔ реальные трения и свойства, о которых узнают слишком поздно | Выявляет скрытые издержки (настройка, очистка, лимиты, поддержка) | `ideas`: выбор конструктора отчётов по тарифу ↔ жалобы после переноса реальных таблиц |
| **Симптом ↔ причины** | Наблюдаемый сбой ↔ независимые группы причин (код, среда, данные, внешний лимит) и недостающие данные | Запрещено выбирать одну причину без достаточных доказательств | `dev`: рост таймаутов HTTP-клиента ↔ исчерпание пула сокетов, DNS-кэш или троттлинг сервера |
| **Кому мешает ↔ кому не мешает** | Контекст страдающих пользователей ↔ контекст тех, для кого проблема незаметна (стек, масштаб, модель, опыт, среда) | Предотвращает ложный приоритет до сравнения условий применения | `dev`: влияние холодного старта функций на API ↔ фоновые воркеры, где задержка не критична |

## 4. Международная развилка (`intl`)

Используется в режиме `ideas`, когда нужно опираться на зарубежный корпус без подмены им локальной аудитории.

1. **Две независимые выборки по одинаковым направлениям:** координатор задаёт единый список направлений (на основе `map` на обоих рынках) и ведёт два отдельных потока — международный и локальный. Объединять сигналы до сравнения запрещено.
2. **Матрица сравнения рынков:** каждое направление в `report.md` получает строку в таблице:

| Направление | Международный корпус | Локальный корпус | Статус сравнения |
|---|---|---|---|
| `<направление>` | ссылки `(F101)` | ссылки `(F201)` | `в обеих` / `только международная` / `только локальная` / `противоречит` / `не найдено` |

3. **Три слоя переноса:** для каждого зарубежного сигнала раздельно фиксируются:
   - **Механизм** — универсальная причина или ограничение задачи и от каких условий оно зависит.
   - **Опыт автора** — единичное наблюдение конкретного пользователя в его среде; не доказывает массовость на локальном рынке.
   - **Локализация** — право и регуляторика, платежи, язык, доступность сервисов и железа, цены, инфраструктура и привычные процессы.
4. **Цепочка переноса:** каждый переносимый сигнал проходит формат:
   `фраза → смысл → механизм → оценка переноса → локальная гипотеза → локальная проверка` + обязательная строка `что нельзя утверждать`.

**Пример цепочки переноса (`ideas`):**
- **Фраза:** `"let us export raw audit logs or pause sync anytime"`
- **Смысл:** пользователю нужен контроль над выгрузкой истории и остановкой фонового обмена.
- **Механизм:** страх потери данных и непредсказуемого списания лимитов при автоматической синхронизации.
- **Оценка переноса:** средний риск (зависит от местных требований к хранению логов и привычных форматов отчётности).
- **Локальная гипотеза:** локальным командам нужен экспорт журнала действий в CSV/JSON и кнопка паузы синхронизации.
- **Локальная проверка:** проверить локальные форумы/чаты админов и отзывы на аналоги про блокировки и выгрузку логов.
- **Что нельзя утверждать:** локальные пользователи готовы платить именно за эту кнопку без проверки их текущих обходов.

## 5. `factcheck`, `trend` и `delta`

### `factcheck` — проверка обещаний
- Рекламные и официальные формулировки (`origin: vendor`) отделяются от независимого пользовательского опыта (`origin: user`) и замеров.
- Включает обязательный поиск контрпримеров и условий, при которых обещание нарушается.
- Каждое проверяемое обещание получает в `report.md` ровно один статус:
  - `подтверждено` — независимые источники подтверждают заявление в заявленном контексте;
  - `частично` — работает только при оговорках (версия, нагрузка, платный тариф, доработка);
  - `не подтверждено` — независимых подтверждений не найдено или преобладают опровержения;
  - `требует теста конкретной модели` — противоречивые данные или сильная зависимость от конкретной конфигурации/версии.

### `trend` — сравнение периодов
- Обязательны два сопоставимых периода с явными датами (`source_date` в обоих окнах) на одинаковом наборе площадок и типов запросов.
- Учитываются сдвиги самой площадки (модерация, уход аудитории, изменение правил поиска), чтобы спад на одном форуме не выдавался за падение спроса.
- **Запрет:** если нет данных минимум из двух сопоставимых периодов с `source_date`, слово «растёт» (и любые формулировки про рост/падение тренда) в отчёте запрещено.

### `delta` — обновление прошлой разведки
- Переиспользует прежний корпус в `.ai-factory/scout/<slug>/corpus/`.
- Запускаются только углы с новыми событиями, новыми версиями или открытыми вопросами из прошлого `report.md`. Незатронутые направления не пересобираются.
- Прежний `report.md` уходит в `archive/<YYYY-MM-DD-HHMM>/report.md`; новый `report.md` — полный текущий синтез: неизменённые выводы переносятся с прежними ссылками.
- Номера новых разведчиков продолжают прежние (сквозной N по `corpus/`), поэтому новые `F<N>` не совпадают со старыми.
- В разделе `## Изменения с прошлой разведки` фиксируются пять списков (со ссылками на старые и новые `F<N>`):
  1. Новые сигналы;
  2. Подтверждённые прежние выводы;
  3. Ослабленные или опровергнутые выводы;
  4. Новые противоречия;
  5. Что перепроверить следующим шагом.

## 6. «Один поиск — один корпус», веер линз и насыщение

- **Один поиск — один корпус:** не запускай повторный поиск для каждой аналитической линзы. При раздельном поиске на каждом шаге выборка плывёт, результаты линз становятся несопоставимыми, а ранняя ошибка толкования переносится по цепочке. Разведчики собирают единый корпус один раз, а линзы (боли, язык, критерии выбора, обходы, обещания vs опыт, пробелы → идеи, контра, новое — см. [angles.md](angles.md)) применяются параллельно поверх этого же корпуса.
- **Веер линз:** в `quick` линзы прогоняет сам координатор; в `normal`/`deep` их можно распараллелить на субагентах поверх собранных файлов `corpus/*.yaml`. Одновременное сопоставление показывает расхождения — например, когда люди эмоционально жалуются на одно, а выбирают инструмент по совершенно другому критерию.
- **Правило насыщения (когда остановиться):** следующую волну не запускают, когда:
  - новые запросы повторяют уже найденные сигналы;
  - не появляются новые углы и новые пользовательские вопросы;
  - основные противоречия зафиксированы со ссылками на обе стороны;
  - оставшиеся пробелы перенесены в `## Неизвестно` (`open_questions`);
  - собранного достаточно для решения или передачи в `/aif-explore` / `/aif-plan`.
- Повод для следующей волны (`-w2`, `-w3`) только один из двух: обязательный угол не дал находок или обнаружено критичное противоречие в решающем пункте.

## 7. Типовые ответы для проблемных ситуаций

Когда поиск наталкивается на ограничение, используй точную формулировку без домыслов:

- **Поиск не выполнен:**
  > Поиск не подтверждён. Сейчас доступны только локальные файлы проекта или переданные материалы. Могу подготовить гипотезы или план поиска, но не выдаю ответ как результат разведки.
- **Источник недоступен:**
  > Найдено `<N>` релевантных ссылок. Полный текст получен для `<A>` (`full`), фрагменты — для `<B>` (`excerpt`), только метаданные — для `<C>` (`metadata_only`), недоступны — `<D>` (`unavailable`). Выводы ограничены прочитанным текстом; содержимое недоступных страниц не восстанавливается по заголовкам.
- **Источник вне разрешённого списка:**
  > По условиям плана разрешены только `<список разрешённых источников>`. Материалы с других площадок (`<список>`) вынесены отдельно и не смешаны с основным корпусом.
- **Локальных данных мало:**
  > В локальном корпусе недостаточно подтверждений по `<теме>`. Международный сигнал сохранён как гипотеза переноса и не используется как факт о локальной аудитории.
- **Источники противоречат:**
  > Источники расходятся: группа 1 (`<ссылки>`) описывает `<контекст A>`, группа 2 (`<ссылки>`) — `<контекст B>`. Выводы не усредняются; для разрешения противоречия нужно проверить `<условие/тест>`.
