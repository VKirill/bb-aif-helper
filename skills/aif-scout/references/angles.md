# Разбор вопроса, углы и инструменты

## 1. Разбор вопроса

Перед составлением плана прогоняй запрос через три шага (`LI:951-985`, `LI:405-437`):

1. **Природа вопроса:** `how-to/debug` · `choose-tool/compare` · `understand-concept` · `find-prior-art` · `validate-idea/market` · `find-pain/wishes`. Природа задаёт допустимые классы углов: для `how-to/debug` не генерируй продуктовые замены без запроса.
2. **Явное:** объекты, действие, жёсткие ограничения (стек, бюджет, лицензия, ОС), рынок/язык, версии. Явные ограничения имеют абсолютный приоритет над гипотезами.
3. **Достаточность (`sufficiency`):** проверь четыре условия — объект определён, действие определено, есть сценарий/ограничение, понятны конкурирующие трактовки:
   - `sufficient` — собирай полную волну углов;
   - `partial` — запускай волну с явным списком допущений в `open_questions`;
   - `insufficient` — задай пользователю **один** уточняющий вопрос и жди ответа, не запускай веер.

## 2. Скрытые намерения и углы

Четыре типа скрытых намерений (`LI:185-260`):

| Тип | Что ищем | Пример для `/aif-scout` |
|---|---|---|
| `attribute_completion` | Неназванный параметр | Версия API, ОС, масштаб, бюджет |
| `substitute` | Замена или альтернатива | «С чего переходят на X и почему», self-made обходы |
| `complement` | Сопутствующая потребность | Интеграции, миграция, мониторинг рядом с X |
| `scenario_expansion` | Более широкий рабочий сценарий | Кто ещё затронут, в каком процессе возникает задача |

Правила отбора углов (`LI:873-875`, `TGA:698`):
- На волну: **≤ 6 гипотез**, из них **≤ 3 `plausible`** (остальные `implied`).
- Конфликтующие с явными ограничениями вопроса **отбросить сразу**.
- Уводящие в соседнюю тему пометить как **дрейф** (`drift`: не основной вывод, уверенность ниже `high`).
- `speculative` перенести в watchlist (`open_questions`) **без запуска разведчиков**.
- Каждая выжившая гипотеза → угол плана `{id, role, hypothesis, mirror_of?, required, market?}` (`role`: `discovery | validation | constraint | measurement`) + **зеркальный угол** (`mirror_of: <id>`) на опровержение.

## 3. Пять осей пропущенного (режим `dev`)

Для технических вопросов выводи углы из пяти осей (`GIST:416-498`):
1. `failure mode` — что ломается в продакшене и при каких условиях.
2. `hidden information` — что выясняют слишком поздно (скрытые квоты, блокировки, зависимости).
3. `limitation` — когда инструмент или подход перестаёт работать.
4. `disqualifier` — причина сразу отвергнуть вариант (лицензия, EOL, несовместимость).
5. `quantifiable property` — измеримые свойства (лимит запросов, задержка, размер, цена).

## 4. Разведчики и инструменты на хосте

### Режим `dev`

| Разведчик | Что ищет | Инструмент у нас | Риски |
|---|---|---|---|
| Официальный | Доки, changelog, release notes, RFC, миграции | `WebFetch`, `gh release list/view`, `npm` registry | Документация отстаёт от кода; SPA-доки без JS |
| Трекер | Issues, PR, discussions: баги, регрессии, обходы | `gh search issues`, `gh api` | Лимит GitHub issues ~30 запр/мин на всех |
| Сообщество | Stack Overflow, HN, Reddit | Stack Exchange API, HN Algolia API; Reddit — только сниппеты | Reddit напрямую 403 → `SNIPPET_ONLY`, макс. `low` |
| Готовые решения | Как сделали другие, альтернативные пакеты | `gh search code` (~10/мин), `npm` search | Пример в репо ≠ рабочий прод-паттерн |
| Скептик (зеркало) | «X problems», «why not X», deprecated, CVE/GHSA | `gh api /advisories`, `Tavily`, `WebSearch` | Шум эмоциональных жалоб |
| Наука (по запросу) | Алгоритмы, бенчмарки, ML | `arXiv` API (1 запр/3 с), `alphaxiv` | Перенос в продакшен не гарантирован |

### Режим `ideas`

| Разведчик | Что ищет | Инструмент у нас | Риски |
|---|---|---|---|
| Боли | Жалобы на инструменты, «wish X could» | HN Algolia, `Tavily` (`include_domains`), `WebSearch` | Яркая эмоция ≠ влияние на выбор |
| Самоделки | Скрипты и костыли, которые пишут руками | `gh search code/repos`, HN «Show HN», `Tavily` | Единичные энтузиасты |
| Конкуренты | За что хвалят и ругают, feature requests, цены | `gh search issues`, Product Hunt Atom `/feed`, `WebFetch` | Обещания продавца ≠ опыт пользователя |
| Рунет | Хабр, vc.ru, публичные Telegram-каналы | `xmlstock` (Яндекс SERP), `t.me/s/<канал>`, `telegram-user` | `tg` только Mac mini и **последовательно**; глобального поиска в TG нет |
| Скептик (зеркало) | «why we shut down», postmortem, «stopped using» | `Tavily`, HN Algolia | Ошибка выжившего в обратную сторону |
| Наука (по запросу) | Механизм задачи, поведение пользователей | `arXiv` API, `alphaxiv` | Наука не подтверждает рыночный спрос |

**Ограничения по результатам проверки на хосте:**
- `gh search code` (~10/мин) делят все параллельные разведчики; не ставь код-поиск в несколько потоков без бюджета.
- Stack Exchange API (~300/день без ключа) и `t.me/s/<канал>` (~20 последних постов) не требуют ключей.
- `Tavily` (`TAVILY_API_KEY`) и `xmlstock` (`XMLSTOCK_*`) платные — задавай бюджет запросов в брифе до старта волны.
- Поиск Хабр API (`kek/v2` → 400) и `discord-web` (timeout) недоступны; при отказе preflight отмечай это как ограничение покрытия.

## 5. Линзы поверх общего корпуса

Разведчики собирают единый корпус, а линзы толкуют его без новых массовых запросов (`SG:549-800`):

| Линза | На какой вопрос отвечает |
|---|---|
| Боли и сбои | Что ломается, что раздражает, а что меняет выбор или вызывает отказ |
| Язык | Как пользователи называют проблему своими словами (цитаты отдельно от пересказа) |
| Критерии выбора | По каким признакам выбирают и что дисквалифицирует вариант |
| Обходы и замены | Как решают сейчас — скрипты, ручной труд, отказ от решения |
| Обещания vs опыт | Что обещано на лендинге/в README против реальности после внедрения |
| Пробелы → идеи | Чего не хватает и почему существующие решения это не закрывают |
| Контра | Кому проблема не мешает и при каких условиях |
| Новое | Что появилось/изменилось — **только при опоре на находки с двумя разными `source_date`** |

## 6. Шаблоны запросов (`ru` / `en`)

При поиске через `Tavily` используй `include_domains`, через `WebSearch` — `allowed_domains` вместо оператора `site:` там, где инструмент режет синтаксис.

- **Официальный (`dev`):** `"<lib> changelog <version>"` · `"<lib> migration guide breaking changes"` · `"<lib> deprecated OR EOL"` · `"<lib> документация ограничения"`
- **Трекер (`dev`):** `gh search issues "<lib> <symptom>"` · `"<lib> regression <version>"` · `"<lib> workaround"` · `"<lib> ошибка <симптом>"`
- **Сообщество (`dev`):** `"<lib> gotchas"` · `"<lib> vs <alt>"` · `include_domains: [stackoverflow.com, news.ycombinator.com]` · `"<lib> проблемы продакшен"`
- **Готовые решения (`dev`):** `gh search code "<api_symbol> language:ts"` · `"<task> reference implementation"` · `"<lib> production example"` · `"<задача> пример реализации"`
- **Боли и самоделки (`ideas`):** `"X sucks"` · `"wish X could"` · `"I wrote a script to <task>"` · `"<задача> надоело руками"` · `"костыль для <задача>"`
- **Конкуренты (`ideas`):** `"<competitor> pricing limitations"` · `"<competitor> feature request"` · `"alternative to <competitor>"` · `"<конкурент> отзывы минусы"`
- **Рунет (`ideas`):** `xmlstock: "<тема> (site:habr.com OR site:vc.ru)"` · `"почему отказались от <X>"` · `"чем заменить <X>"` · `t.me/s/<канал>`
- **Скептик (`dev`/`ideas`):** `"why not <X>"` · `"why we shut down <niche>"` · `"stopped using <X>"` · `"почему не взлетело <ниша>"`
- **Наука (`dev`/`ideas`):** `"how <mechanism> affects <metric>"` · `"empirical study <topic> limitations"` · `"benchmark <method> failure cases"`

## 7. Глубина и правило насыщения

| Глубина | Разведчиков | Линз | Когда выбирать |
|---|---|---|---|
| `quick` | 2–3 | 1 (синтез сам) | Локальный технический вопрос с низким риском |
| `normal` | 4–5 | 2–3 | По умолчанию для `dev` и `ideas` |
| `deep` | 6–8 + 2-й раунд | 3–4 | Деньги, безопасность, лицензии, необратимые решения (включается сам по признакам риска) |

Диапазон — ориентир, а не норма: сокращение или расширение объясняется одной фразой в плане (`CS:187-206`).

**Правило насыщения (`SG:871-882`):** останавливайся и не запускай следующую волну, когда новые запросы повторяют уже найденные сигналы, не добавляют новых углов/вопросов, основные противоречия зафиксированы со ссылками, а оставшиеся пробелы перенесены в `open_questions`.
