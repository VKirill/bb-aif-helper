# История изменений

## 0.20.0 — 2026-11-19

- Карточки, вкладка и подсказки больше не опрашивают сервер по таймеру: оба 15-секундных `setInterval` и все подписки `useRealtime('changed')` убраны. Чтения идут через общий кэш BB `experimental_useRpcQuery` — одинаковые карточки в чате делают один запрос, неизменённый ответ не перерисовывает экран, после переподключения BB данные перечитываются сами.
- Сервер вместо широковещательного `changed` помечает устаревшими только нужные данные (`bb.rpc.experimental_invalidate`, теги `thread:<id>`, `project:<id>`, `chip-scoring`). Пропали двойные запросы подсказок; кэш снимков не будит клиентов, если изменилось только время сбора.
- Изменения файлов проекта приходят без опроса: пока открыта карточка, хост держит один нативный наблюдатель BB на корень проекта и сообщает только о служебных путях (`.ai-factory/`, `.github/`, `docs/`, `openspec/`, корневые документы и конфиги). Правки исходного кода чтений не вызывают. При потере наблюдателя — одно обновление и одна повторная постановка, резервного таймера нет.

## 0.19.0 — 2026-11-19

- Параллельное выполнение задач `/aif-implement`: у роли «Код» при «Другая модель» в «Исполнителях» появился переключатель **Параллельно** (Выкл · 2 · 3 · 4). Выбор хранится параметром `parallel` в `phases.implement.model` и попадает в «Модели по умолчанию» вместе с моделью.
- Группы задач считает плагин, а не агент: чистый модуль `parallel-plan.ts` разбирает `Depends on`, `Files:`, фазы и маркеры commit/deploy; пересекающиеся файлы, задачи без понятного списка файлов и одиночные commit/deploy не попадают в общую группу. Расчёт виден командой `bb plugin run aif-chat groups --target <план> [--max N] [--json]`.
- Каждая задача группы запускается отдельным тредом `AIF · <план> · <taskId>` в собственной git worktree-копии проекта от текущего коммита: координатор создаёт её сам (`git worktree add --detach <копия> refs/heads/<ветка>`) и запускает исполнителя на ней (`bb thread spawn --environment <копия>`), поэтому режим работает и в папке-проекте BB, где каждый плагин — отдельный репозиторий; исполнитель не коммитит, а координатор переносит правки патчами `git apply --3way` по одному с проверкой каждой задачи. Между группами — локальный коммит `chore(aif): …` без push. Чужие незакоммиченные изменения, конфликт патча или ошибка расчёта групп (ultra, OpenSpec, цикл) останавливают параллельный сценарий. В «В работе» у исполнителя в отдельной копии — метка «отдельная копия».
- При включённом режиме в `.ai-factory/skill-context/aif-plan/SKILL.md` появляется управляемый блок правила: у каждой задачи плана обязательны конкретные `Files:` и `Depends on`; при выключении блок удаляется.

## 0.18.0 — 2026-11-19

- Панель собрана в стиле группированного списка iOS: секции с мелким серым заголовком и блоком без рамки, строки разделены линиями, вложенные рамки убраны. Стиль действует только во вкладке — карточки в сообщениях не изменились. На узкой панели (контейнер уже 448 px) переключатель «Навигация | Настройки» переносится второй строкой шапки двумя равными половинами.
- «Подготовка проекта»: шаг запускается стрелкой **›** в строке, нажатие на название (или «?») раскрывает описание и «Пропустить»/«Вернуть»; отдельных кнопок запуска и пропуска в строке больше нет.
- «Исполнители»: вся строка роли — кнопка «Изменить» с названием, моделью и уровнем второй строкой и «›» справа.
- Кнопки-подсказки: команда, написанная агентом целиком в inline code (например, `` `/aif-fix … so npm test passes` ``), переносится в чип с аргументами (одна строка, до 300 символов) и при пустом поле отправляется сразу. При непустом поле команда встаёт первой строкой без отправки. Чипы неустановленных skills скрыты, кроме следующего шага из gate; пилюля режима AI Factory не попадает в черновики команд.
- «Оценка кнопок» в «Настройках» (выключена по умолчанию): при двух и более доступных командах Gemini Decisions API (`gemini-decision-1`) один раз на ответ оценивает, какую команду вероятнее нажмут, — на чипах появляются проценты, порядок по убыванию. В Google уходят последний ответ агента (до 20 000 символов) и список команд. Ключ — из Env Catalog (хранится только имя, значение читается перед запросом через `env_get_value`) или вручную секретной настройкой `decisionsKey` (0600, во вкладку не попадает). Ошибки показаны в блоке без повторов; ключ и текст ответа в журнал не пишутся.

## 0.17.0 — 2026-11-19

- Режим AI Factory для проекта: кнопка в поле ввода (новый чат и открытый тред) включает ведение задачи командами `/aif-plan` → `/aif-implement` → `/aif-verify` → `/aif-commit`; агент получает инструкции через `bb.agents.configure` — читать `.ai-factory/DESCRIPTION.md`, `ARCHITECTURE.md` и `.ai-factory/skill-context/`. Режим хранится на проект и не действует в дочерних тредах.
- Идущий чат и компакция: после включения режима или события `thread/compacted` в поле ввода вставляется упоминание «AI Factory», которое при отправке передаёт агенту текст режима как скрытый контекст. У ACP-провайдеров инструкции после компакта могут потеряться — пилюля восстанавливает их; у Claude Code и Codex она безвредна. Выключение режима убирает пилюлю из черновика.
- Пустой ответ агента при включённом режиме и отсутствии его команд показывает до трёх ближайших действий («Следующий шаг»).
- «В работе»: у дочерних тредов видны запрошенные модель и уровень рассуждения (`client/turn/requested`), подтверждённая провайдером подмена (`provider/modelFallback`, только Claude Code) и расхождение с выбранной моделью («⚠ Ожидалась модель …»).
- Упоминание `@AI Factory` в поле ввода доступно вручную: поиск по `aif`/`фабрика`/`режим`.

- Без установки AI Factory в проекте доступен встроенный flow: исследование → Markdown-план → выполнение → проверка → коммит. Используются промпты плагина, без вызовов отсутствующих skills и загрузки инструкций по сети.
- Добавлена отдельная кнопка установки AI Factory: агент переиспользует существующий CLI или устанавливает официальный пакет, инициализирует текущий поддерживаемый runtime и проверяет результат. Просмотр карточки и обычные базовые шаги установку не запускают.
- Базовые планы обнаруживаются в `.bb-aif-helper/plans/*.md`, задачи и прогресс показываются в панели. После установки AI Factory выбор базового плана освобождается, файлы сохраняются без автоматической миграции.
- Сохранены защита от неявного выполнения следующих шагов, stale/busy/pending/duplicate/uncertain dispatch и блокирующего gate. Invalid-конфигурация не обходится базовым режимом.

## 0.7.5 — 2026-11-05

- При незакоммиченных файлах текущего проекта «Подготовить коммит» предлагается первым следующим действием независимо от активного плана, в том числе после архивирования или при нескольких кандидатах. Кнопка не дублируется с существующим этапным предложением.
- Git status проекта передаётся отдельно от dirty настроенного checkout AI Factory; clean/unknown не создают дополнительное предложение. Старые сохранённые снимки получают unknown до перечитывания.
- Запрос aif-commit требует просмотра diff и определения состава коммита с сохранением несвязанных файлов. Занятость, вопросы, актуальность файлов и блокирующие gate перепроверяются перед отправкой; открытия панели недостаточно для запуска.

## 0.7.4 — 2026-11-05

- Поиск команд в обычном тексте ответа поддерживает `/aif…` наряду с `$aif…`. Рекомендации после финализации `/aif-mode sync` и `/aif-commit` появляются как две кнопки с префиксом текущего runtime.
- Для mode sync сохраняется только фиксированная подкоманда `sync`; произвольные аргументы/флаги и shell-текст не передаются. Пути, URL и некорректные префиксы не считаются командами.
- Сохранены проверка установленных skills, отдельное скрытие предложений, блокировка commit при FAIL и guards доставки. Gate JSON остаётся отдельным источником с прежним allowlist.

## 0.5.0 — 2026-11-02

- Общий кэш снимков в памяти и локальной SQLite-базе плагина. Вместо двухсекундного кэша на карточку — до минуты для обычного чтения; сохранённый снимок показывается сразу и обновляется в фоне. Кэш переживает reload, ограничен 100 снимками и 1 MiB на снимок; данные старше суток не используются для быстрого показа.
- Параллельные чтения одной рабочей среды/цели объединяются; этапы карточек и состояние чатов применяются отдельно. Чтение истории gate также объединено, сохранённые результаты показываются до фоновой сверки.
- Кнопка ↻, agent status/CLI и запуск действия явно обходят кэш. Фоновые ошибки сохраняют старую карточку с предупреждением и задержкой перед повтором; принудительное чтение возвращает ошибку, а не старые данные. Устаревший запрос не перезаписывает новый снимок после invalidation.
- Внизу карточки показаны источник, время снимка и фоновое обновление. Занятость и открытые вопросы читаются отдельно из актуального состояния BB.

## 0.4.0 — 2026-11-02

- Кнопки verify/rules/security/review, подготовки/прохождения QA, качества и CI перенесены в соответствующие строки секции проверок. Общий ряд кнопок снизу убран.
- На живом завершении валидного gate сохраняется отдельный отпечаток входов проекта. При неизменных входах повторный gate отключён с причиной «без изменений», в том числе через дублирующую workflow-кнопку и предложение команды. Сервер заново проверяет состояние перед отправкой.
- Отпечаток учитывает Git HEAD/index/diff/status, canonical target, установку, прочитанные metadata и содержимое неигнорируемых untracked files. Этап UI и время не сбрасывают блокировку. После изменения входов повторная проверка доступна.
- Старые отчёты не привязываются к сегодняшним файлам. Ошибки Git/чтения, превышение лимитов, submodules и неизвестная привязка оставляют повтор доступным. Это сравнение файлов с состоянием при фиксации результата, а не подтверждение PASS или готовности к done.
